## Abstract

This proposal defines the data model for a public registry of ethics cases in psychedelic and mental health communities: what a record contains, how it is de-identified, when it may be published, how corrections work, and what constraints bind any AI agent querying it.

It is written for implementers. The governance questions it depends on — who adjudicates, how severity is assigned, what the disclosure tiers are — are defined in ECP-1.

## Motivation

The field operates on anecdote. Nobody knows the actual distribution of concern types, how often they are interpersonal rather than ethical violations, or how quickly they resolve, because nobody has been counting. That absence has consequences in both directions: institutions can hide patterns behind the claim that they received no formal complaints, and individual providers face accusations that carry disproportionate weight because there is no context for how common such concerns are.

There is a second, deeper gap. Indigenous cultures verify repair through communal witnessing and cultural memory — the community was present, the elders remember, the account is carried forward. Western communities in this field have no equivalent. People move between communities, organizations form and dissolve, and every accountability crisis starts from nothing. Process artifacts and an accumulating record are the substitute for what other traditions hold organically.

The constraint is that ethics case records are among the most sensitive data that exists, and a registry that re-identified people would inflict exactly the harm the standards exist to prevent. This specification exists to make the record useful and the privacy structural rather than aspirational.

## Specification

### Design constraints

Four constraints shape every decision below.

**De-identified by construction, not by redaction.** Records are generated from structured fields captured during adjudication. They are not narratives that have had identifying details removed. Redaction fails at inferential identifiers; construction avoids creating them.

**A measurement instrument, not a screening instrument.** The registry shows the field what is happening in aggregate and how cases were reasoned. It cannot tell a community whether a specific person has a history, because it holds no identities. This is the intended tradeoff and should be stated plainly wherever the registry is presented.

**Structured over narrative.** Every field that can be a controlled vocabulary is one. Free text is confined to reasoning, written at the level of which standard applied and why rather than what a person did.

**Irrevocable once published.** Open licensing and mirroring mean records cannot be recalled. Corrections therefore work by supersession, never deletion.

### Provenance classes

Three distinct sources feed the registry. They are not equivalent and must never be merged.

| Class | Source | What it represents | Weight in retrieval |
|---|---|---|---|
| `adjudicated` | Independent adjudication body, at case closure | A finding reached through documented process | Precedential. May be cited as precedent. |
| `peer_practice` | Community-submitted dilemma and its own reasoning | How a community reasoned, unverified | Illustrative. Labeled as peer practice. Not precedent. |
| `advisory_query` | Facilitator question posed to the AI agent, with response | A question pattern in the field | Query data only. Never surfaced as guidance. |

`provenance` is required on every record. Any interface displaying records must display the class.

### Record schema

#### Identity and versioning

| Field | Type | Notes |
|---|---|---|
| `record_id` | string | Stable public identifier. Used for citation. |
| `provenance` | enum | `adjudicated` \| `peer_practice` \| `advisory_query` |
| `schema_version` | string | Version of this ECP the record conforms to |
| `published_at` | date | Publication date, not case dates |
| `supersedes` | string \| null | `record_id` of the record this replaces |
| `superseded_by` | string \| null | Set when a later version exists |
| `record_hash` | string | Cryptographic hash published at release; proves non-alteration |

#### Classification

| Field | Type | Notes |
|---|---|---|
| `category_final` | enum | `1` (interpersonal, non-physical) \| `2` (physical component alleged) |
| `category_changed` | boolean | Whether category changed during the case |
| `category_change_basis` | text \| null | Required if changed. Must state the affirmative basis. |
| `severity_provisional` | integer 1–5 | Assigned at intake for resourcing |
| `severity_final` | integer 1–5 | Assigned at closure |
| `severity_changed` | boolean | Calibration signal |
| `severity_change_reason` | text \| null | Required if changed |
| `harm_type` | enum | See vocabularies |
| `role_class` | enum | See vocabularies |
| `setting_class` | enum | See vocabularies |
| `modality_class` | enum | See vocabularies |

#### Timing

No incident date, filing date, or closure date is ever published. Only durations and coarse buckets.

| Field | Type | Notes |
|---|---|---|
| `days_to_category_assigned` | integer | From date raised |
| `days_to_finding` | integer | From date raised. The headline timeliness metric. |
| `days_at_level` | map<int,int> | Level → days spent. Shows where cases stall. |
| `incident_to_filing_bucket` | enum | `<1mo` \| `1-6mo` \| `6-12mo` \| `1-3yr` \| `3yr+` \| `unknown` |

#### Process

| Field | Type | Notes |
|---|---|---|
| `pathway` | enum | `both_parties` \| `proceeded_without_complainant` |
| `complainant_participation` | enum | `participated` \| `declined` \| `withdrew_to_pursue_criminal` |
| `respondent_submission` | enum | `submitted` \| `declined` \| `declined_under_counsel` |
| `dialogue_held` | enum | `yes` \| `skipped_documented` \| `not_required` |
| `standards_satisfied` | array<int> | Which of the Nine Standards were verified |

`respondent_submission` distinguishes `declined` from `declined_under_counsel` deliberately. Both are non-participation; only one reflects on the person. Collapsing them would let the record imply bad faith where there was legal caution.

#### Outcome

| Field | Type | Notes |
|---|---|---|
| `finding` | enum | `violation_established` \| `violation_not_established` \| `no_process` \| `dismissed` \| `referred_out_of_scope` \| `withdrawn` |
| `recommendation_class` | enum \| null | See vocabularies |
| `reasoning` | text | Which standard applied and why. Standard-level, not act-level. |
| `not_decided` | text \| null | What the finding explicitly does not determine |
| `pattern_flag` | boolean | Set where a non-physical concern may form part of a pattern |

`no_process` is the Category 1 non-participation outcome: a concern was raised, the complainant declined to participate, and the person named is fully exonerated with no finding held against them. Publishing these matters. A registry containing only adverse findings reads as a blacklist; one containing the full distribution of outcomes is evidence of fairness.

`not_decided` exists because precedent is only usable if its limits are stated. Without it, retrieval will over-extend findings into territory they never addressed.

#### Community response

| Field | Type | Notes |
|---|---|---|
| `community_action` | enum | `acted` \| `did_not_act` \| `no_response` \| `pending` |
| `aligned_with_recommendation` | boolean \| null | Null where not applicable |
| `days_finding_to_community_action` | integer \| null | |

Adjudication closure and community action are separate events. Community action is recorded but is not a condition of closure, because the adjudication body does not control it. The absence of a response is itself recordable without the community's cooperation.

### Controlled vocabularies

Initial values. Extension requires the ECP-0 amendment process.

**`harm_type`** — `physical_boundary` · `sexual_misconduct` · `coercion` · `power_abuse_nonphysical` · `deception` · `confidentiality_breach` · `scope_violation` · `financial_conflict` · `communication_rupture` · `administrative_error` · `other`

**`role_class`** — `licensed_facilitator` · `unlicensed_facilitator` · `clinician` · `guide_or_sitter` · `community_leader` · `board_or_admin` · `trainer` · `participant_or_seeker` · `staff` · `other`

**`setting_class`** — `ceremony_or_session` · `intake_or_screening` · `integration_or_aftercare` · `training_or_supervision` · `community_or_administrative` · `online_or_remote` · `other`

**`modality_class`** — `psilocybin` · `mdma` · `ayahuasca_or_dmt` · `ketamine` · `lsd` · `other_psychedelic` · `non_pharmacological` · `not_applicable`

**`recommendation_class`** — `facilitated_dialogue` · `acknowledgment_and_amends` · `restitution` · `training_or_supervision` · `practice_restriction` · `role_change` · `removal_from_community` · `systemic_change` · `no_recommendation`

`practice_restriction`, `role_change`, and `removal_from_community` are recommendation classes only. The adjudication body recommends; it does not impose. See ECP-1 on authority boundaries.

### De-identification rules

**Never recorded:** names of any person, organization, community, or place; locations at any granularity; incident dates; contact details; any direct identifier.

**Recorded as class only:** role, setting, modality. Never as free-text description.

**Reasoning field:** written at the level of which standard applied and why. "Categorized as Category 2 because the concern described physical contact; complainant declined to participate, so the process proceeded on available evidence under the Category 2 pathway" carries full precedential value and nothing identifying. Narrative describing what a person did does not belong in this field.

**Uniqueness check.** Before publication, test whether the tuple (`category_final`, `harm_type`, `role_class`, `setting_class`, `modality_class`) is unique across the published registry. If it is, generalize one field one level before release. Uniqueness is identifying even with no names.

**Aggregate suppression.** Any aggregate cell below the suppression threshold is not published. Threshold is a governance parameter; see open questions.

**Small-community rule.** Where a contributing community is small enough that case-level records are identifiable by pattern, publish aggregate statistics only until the contributing pool is large enough to provide meaningful anonymity.

### Ingestion paths

De-identification differs by provenance and must be implemented separately for each.

**`adjudicated` — automatic derivation.** The adjudication system holds the identified working record. On closure it emits a registry record composed entirely of structured fields already captured during the case. There is no separate submission and no scrubbing step, because no identifying content is ever transferred. The identified working record remains under the confidentiality and destruction rules of ECP-1.

This is the preferred path and imposes a requirement upstream: the adjudication workflow must capture these fields as structured values at the time of decision. They cannot be reconstructed from prose afterward.

**`peer_practice` — submit, scrub, review, approve.** Contributor submits narrative. Automated pass removes direct identifiers. Second automated pass flags candidate inferential identifiers rather than removing them. Human review resolves flags and runs the uniqueness check. Contributor approves the de-identified version. Raw submission is destroyed on approval.

The scrubber must be self-hosted so raw input never leaves the operator's environment. Only the de-identified record is stored.

**`advisory_query` — scrub at capture.** The same scrubber runs on input before storage, with a consent notice at point of use. Stored records carry no identifying content and are never surfaced as guidance.

For all non-automatic paths, the submitter cannot be the sole approver. A submitter knows their own identity but will not reliably recognize what identifies the other party, or what identifies them to someone holding different knowledge.

### Publication rules

**Two gates.** Automated uniqueness and threshold checks, then human review of the reasoning field. Both must pass.

**Publication lag.** Records publish no sooner than a defined interval after closure, or in periodic batches. This breaks the link between a case concluding and a record appearing, which is otherwise informative in a small community. Interval is a governance parameter.

**Open-case status is coarse.** While a case is open, only `open`, `under_review`, or `pending_milestone` may be shown. Severity and category are not published until closure. A case publicly sitting at a high severity level broadcasts a suspicion no finding has yet supported.

### Correction and versioning

Records are never deleted. A correction publishes a new record with `supersedes` set to the prior `record_id`, and the prior record is marked `superseded_by`. Both remain retrievable. The reason for supersession goes in the new record's `reasoning` field.

Each published record carries a `record_hash` computed at release. This proves the record existed at that point and has not been altered since, without requiring a blockchain or creating right-to-erasure conflicts.

### AI agent constraints

The agent is an open-source retrieval and reasoning interface over the registry. These constraints are part of the specification, not implementation preferences.

**It surfaces precedent; it does not decide.** The agent may identify relevant prior records, summarize reasoning, and state which standards were applied. It must not output a category, a finding, or a recommendation for the situation being asked about. A tool built to support fair process cannot pre-empt it.

**It labels provenance on every result.** An `adjudicated` finding and a `peer_practice` contribution must never appear as equivalent authority.

**It cites `record_id` for every claim.** Unsourced synthesis is not permitted.

**It surfaces `not_decided`.** Where a cited record explicitly did not determine something, the agent must say so rather than allowing inference to fill the gap.

**It refuses screening queries.** Attempts to determine whether a specific person or organization has a history must be declined with an explanation that the registry is de-identified by design. This will be attempted often and the refusal must be robust.

**It warns on thin precedent.** Where fewer than a defined number of relevant records exist, the agent states that precedent is limited. A precedent-trained advisor otherwise entrenches whatever was in the earliest cases.

Apache 2.0 is used for software rather than MIT for its express patent grant, its default inbound contribution terms, and its explicit non-grant of trademark rights. CDLA-Permissive-2.0 is used for the dataset because it addresses sui generis database rights and was purpose-built for collaboratively contributed data, including clarity on machine-learning use.

Inbound contribution of case data requires a separate Data Contributor Agreement. Outbound licensing does not establish the right to contribute; that depends on the consent chain from the original participants.

## Costs and who bears them

**Adjudication bodies** bear the requirement to capture structured fields at the time of decision rather than writing narrative and extracting later. This is real added discipline during the hardest part of a case.

**Contributing communities** bear submission and approval labour on the `peer_practice` path, including a review step they cannot delegate entirely.

**The registry operator** bears the de-identification pipeline, self-hosted scrubbing infrastructure, human review of every reasoning field before publication, and the uniqueness checks. Human review is the dominant ongoing cost and cannot be automated away.

**Implementers** bear conformance work: adopting the schema, the vocabularies, and the agent constraints rather than designing their own.

**Everyone** bears the cost of the central tradeoff: because the registry holds no identities, it cannot warn a community about a specific person. That limitation is paid for in exchange for privacy that holds.

## Benefits and who they accrue to

**The field** gets a factual baseline in place of anecdote — the actual distribution of concern types, how often they are ruptures versus violations, and how quickly they resolve.

**Communities** get precedent. A community facing its first serious concern can see how comparable cases were reasoned rather than improvising under pressure.

**People in future cases** benefit from consistency, because published reasoning makes inconsistent treatment visible.

**Providers collectively** get context that protects them from a dynamic where a single accusation carries disproportionate weight for lack of any comparison.

**Researchers and policymakers** get a dataset that does not currently exist, with documented provenance and de-identification methodology.

**People whose cases are recorded** get privacy that is structural rather than promised, and a record that cannot be quietly altered after the fact.

## Alternatives considered

**Publishing full case narratives with names redacted.** Rejected. Redaction fails at inferential identifiers, and in a field this small a narrative with role, setting, and sequence intact identifies people without any name present.

**Publishing nothing at case level; aggregate statistics only.** Considered seriously and retained as the fallback for small communities. Rejected as the general rule because aggregates alone cannot carry precedent, and precedent is what lets communities learn from each other rather than each starting from nothing.

**Including incident dates.** Rejected. Combined with role and setting, a date is among the strongest re-identification vectors. Elapsed-time buckets preserve the analytic value — reporting delay is itself informative — without the anchor.

**CC BY 4.0 for the dataset.** Workable, since 4.0 covers sui generis database rights. Rejected in favour of CDLA-Permissive-2.0, which was purpose-built for contributed datasets and is explicit about machine-learning use.

**Apache 2.0 for the dataset.** Rejected as a category error. Apache is a software license; its core terms — source form, object form, derivative works, NOTICE — do not map onto data, it does not grant database rights, and much of the registry is uncopyrightable fact.

**A blockchain for record integrity.** Rejected. Published hashes provide the same proof of non-alteration without the cost, governance complexity, or the direct conflict between immutability and right-to-erasure obligations.

**Deleting incorrect records.** Rejected as unachievable once records are openly licensed and mirrored, and undesirable because it would let the record be quietly revised. Supersession preserves the correction trail.

**An AI agent that categorizes or recommends.** Rejected. A tool that pre-empts the categorization gate would substitute automated judgment for the documented human reasoning this framework exists to require.

## Open questions

1. **Suppression threshold.** What minimum cell count for aggregate publication, and what minimum registry size before case-level records publish at all.
2. **Publication lag interval.** How long after closure.
3. **Pattern definition.** What constitutes a pattern for `power_abuse_nonphysical` cases. Multiple complaints about a single incident are not a pattern; multiple independent complaints describing similar behavior across separate incidents at different times may be. The independence test and the count threshold are both open. See ECP-1 open questions.
4. **Consent chain for bulk imports.** Whether existing case archives held by partner organizations carry terms permitting secondary use of de-identified content.
5. **Portable findings.** Whether a separate, consent-based mechanism should exist allowing a finding to follow a person between communities. This would require entirely different privacy rules and is out of scope for this specification.

*This is a working draft, offered for open debate. Feedback, adaptation, and forks are welcome.*
